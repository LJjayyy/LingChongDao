# Codex 权限观察误报修复（0.1.29）

用户报告：岛内显示橙色「待确认」和「1 秒后返回原工具处理」，但仅有「打开会话」，没有可执行的批准或拒绝。

## 已复现的原因

此前所有 `PermissionRequest` 都被归为审批，即使 Codex 没有提供灵宠岛能识别的请求关联 ID。helper 对这种无交互通道的事件会立即返回 `{}`，让来源照常处理；界面却仍设为等待审批，并把最多 2 秒的传输截止时间显示为审批倒计时。它只能证明观察到一次来源权限检查，不能证明用户此刻需要作决定。

修改前，新增 AppModel 回放在「无 ID 权限观察不能成为审批提醒」断言失败；即时空响应的断言通过。修改后，同一场景与真实审批正对照均通过。

截图当时的原始 Hook 没有保存，不能逐字段证明该次就是缺少 ID，也不能推断来源已自动放行。只读查看对应来源会话确认这次操作后来正常结束，不代表截图当时的准确审批状态。

## 当前行为

- Codex 没有可用关联 ID：归为 `permissionObserved`，只更新「来源权限检查」摘要；没有橙色待办、审批对象或倒计时。
- 空白 ID 视为缺失；前一个别名为空白时，仍寻找后续有效别名。
- 不改变原来的运行、结束、失败、中断或未读状态；不清除已有的真实审批或问题。未知会话单独收到观察时不凭空显示任务。
- 带有效关联 ID 的请求继续使用原审批流程与能力判断。复杂操作保留原来的返回来源或拒绝能力。
- 非交互审批卡片不显示「返回原工具处理」倒计时。Qoder、Buddy 和通用来源的协议保持原样。

无 ID 表示灵宠岛无法可靠关联审批，来源仍可能要求用户处理。修复不会替来源允许、拒绝或修改信任状态，也无需重新安装或审查 Codex 插件。

## 验证

运行 `./scripts/verify-approval-observation.sh` 可重复执行 Core 34 项与 AppModel 19 项检查。使用合成 JSON、内存状态、隔离偏好设置及临时可执行文件，不启动真实来源、不更改来源配置。测试进程设置 20 秒超时。

同时通过 Core 通用验证 37 项、失效请求 16 项、原应用审批 13 项、状态汇总 14 项，以及发布构建中的插件合同 17 项；来源路由、会话跳转与 Buddy 验证脚本也正常完成。独立只读复审未发现必须回修的问题。

本机 0.1.29（build 30）已验证：唯一模拟会话先开始，再收到无 ID 权限观察，展开列表保持绿色运行中，收起态仍计为运行；Stop 后再收到观察仍为本轮结束；未知会话不显示；SessionEnd 后的观察不复活任务。所有模拟 Hook 均返回 `{}`，未操作任何真实审批。模拟会话已用 SessionEnd 清理。

安装位置固定为 `/Applications/灵宠岛.app`；本次未更改防休眠、来源连接、插件信任或来源权限设置。
