# 灵宠岛名称与兼容迁移

从 0.1.13 起，当前文档、工程与运行产物采用以下名称：

| 用途 | 当前名称 |
| --- | --- |
| 应用、菜单、窗口、Hook 文案 | 灵宠岛 |
| 项目目录 | 灵宠岛 |
| Swift Package、主 Target、可执行程序 | LingChongDao |
| 主应用源码 | Sources/LingChongDao |
| Hook helper | lingchongdao-hook |
| Bundle ID | local.lingchongdao.app |
| 本地数据 | ~/Library/Application Support/LingChongDao |
| 本地桥接 | ~/Library/Application Support/LingChongDao/run/bridge.sock |
| Hook 归属标记 | lingchongdao-managed:v1 |
| Codex 插件 / marketplace | lingchongdao-codex / lingchongdao-local |

老板鼠是默认灵宠的角色名，不是另一款应用。

## 既有安装

启动前检查旧版和新版应用是否已运行，避免两个版本同时处理请求。旧版偏好仅复制应用自身的设置及草稿，并保留新版已有的值。

既有数据目录移动至当前目录，旧路径保留一个精确指向新目录的兼容链接。已加载旧命令的来源会话仍能访问原 helper 和 socket；验证归属后复制 helper 至新文件名。manifest 保留原始内容，连接修复时仅替换其精确记录且指向已知路径的历史命令。未知同名命令不会因名称相似而被接管。

双数据目录冲突、未知 helper、非预期符号链接会阻止自动迁移并保留数据。隔离预览使用独立临时目录，不迁移真实数据。更新 Hook 定义后，来源应用需要刷新；Codex 可能要求重新审查，应用不修改信任状态。

## 历史名称的保留范围

旧身份字面量只用于迁移、旧命令识别、构建清理、兼容验证和历史证据。公开日志中的历史名称保持原样，维护者真实用户目录使用占位符脱敏；它们不代表当前工程或安装路径。
