# 灵宠岛 · UIUX 设计基线

版本：0.1 · 2026-10-23。参考产品：macOS Qoder CN 0.4.9。当前交付为设计规格与浏览器交互原型。原型已做视觉与交互检查；运行中 Qoder CN、真实来源与原生窗口的实机验收仍待完成。

## 1. 设计北极星

**用户应像使用当前 Qoder CN 灵动岛一样查看和处理 AI 任务，只是在同一个岛里同时看到 Qoder CN、Codex 等来源。**

方向已确定：照当前 Qoder CN 还原 UI 与 UX，再在其既有语法中延伸必要能力。不另做视觉方向、不换布局体系、不把灵动岛扩成完整聊天客户端。新增来源以后，悬停、展开、输入、审批、回到任务的操作习惯仍然一致。

主要用户任务依次为：看进展 → 发现需要自己决定的事 → 在轻交互范围内处理 → 回到原会话。来源接入能力不足时，在同一视觉位置提供回原应用的动作。

本文件依据现有[《调研与产品方案》](调研与产品方案.md)、`work/qoder-local-evidence.md` 与用户设置截图。以以下三种标记区分证据，不能互相替代：

| 标记 | 含义 | 可用于什么 |
| --- | --- | --- |
| **S · 截图直接复刻** | 用户提供的设置页画面和文字 | 设置结构、控件位置、两类收起预览、文案语义 |
| **P · 包静态还原** | 本机 0.4.9 安装包的逻辑、样式与常量 | 活动态、时序、尺寸、排序、问答/审批及多屏规则的初始规格 |
| **E · 新增延伸** | 为独立、多来源应用提出的设计 | 来源标注、连接管理、回原会话及最小任务总览 |

P 是实现证据，不等于实机表现已确认。后续录屏或截图若与 P 有差异，应在差异记录中说明原因，不能静默把新设计写成 Qoder 现状。

| 设置 | 原有分组、条目顺序、右侧开关、说明文字、分隔线、双预览、宽/高滑杆和恢复默认 | S + P |
| 多屏 | 相同任务投影、各屏独立展开；全局只有一块屏幕可固定请求并输入 | P |

任务优先级固定为：**等待回答 → 其他等待（含权限）→ 失败/中断 → 完成 → 执行中**；同级按最近更新时间倒序。单个会话同时有多个交互时，优先展示用户问题。不得改成“权限永远第一”或按来源分组后破坏排序。隐藏、归档、侧边对话等不直接进入岛列表；终态提示跟随未读/清理状态，没有依据增加统一的几秒后消失计时器。

宠物的位置、占比、状态动画职责与参考一致。产品名称和形象的最终素材选择不作为重新设计结构的理由；原型中的素材状态由交付说明单独交代。

## 3. 允许的最小延伸

### E1 · 来源标注

在展开卡片、运行列表已有的标题/元信息行中加入低强调的来源文字，例如 `Codex`、`Qoder CN`，项目名沿用既有会话描述位置。尽量不增加一整行，不增加彩色品牌底板，不把收起栏改成多个应用入口。

来源文字必须可见；空间不足时先截断任务标题或项目长名，不能把用来区分同名任务的来源隐藏掉。原会话标题与当前活动仍是主要内容，来源只是识别依据。收起栏继续呈现聚合状态，第一版不另加来源筛选器。

### E2 · 连接管理

连接管理放在工作台的设置中，视觉沿用截图已确认的语法：浅色页面、圆角分组容器、左侧标题和灰色说明、右侧操作、细分隔线。每个来源一行，展开后仍使用同类设置行，不引入数据看板、彩色大卡或新的装饰体系。

| 设置内容 | 界面呈现 | 说明 |
| --- | --- | --- |
| 来源名称、客户端版本 | 主标题 + 次要说明 | 例如 Codex；不让用户阅读协议名才能判断连接对象 |
| 连接状态 | 右侧文字：未连接 / 连接中 / 已连接 / 需要处理 | 用既有状态色做小范围提示 |
| 可用交互 | 一句明确说明 | 例如“可查看进展、处理权限请求；问题请前往 Codex 回答” |
| 连接 / 检查连接 / 断开 | 同一操作位置 | 操作过程中显示就地反馈，失败保留当前位置 |
| 所需用户动作 | 就地说明与对应动作 | 只在实际需要时展开；不把原始日志作为主要内容 |

连接成功由真实回执决定。演示原型的连接状态使用可控测试数据，界面内不写制作说明；交付说明要写明尚未连接真实来源。

### E3 · 返回原会话与最小工作台

把 Qoder 专属跳转文案按来源替换：`在 Codex 中回答`、`在 Qoder CN 中查看`。调用目标仍是同一个会话。支持精确定位时打开对应会话；只能打开应用时，使用 `打开 Codex` 等准确文案，不承诺已定位任务。

空闲点击改为打开本应用的工作台，这是独立应用必需的入口延伸。工作台只含任务定位和连接设置：任务行复用岛内标题、来源、状态和摘要层级，入口直接回来源应用；设置使用上面的分组行。不新增聊天输入区、文件审阅器、模型切换、宠物市场或统计仪表板。

## 4. 状态与交互矩阵

状态分三层：任务状态、岛的展开/收起状态、请求的编辑状态。鼠标离开只改变呈现，不修改任务状态；完成提示清理后，任务在总览中仍保留已完成状态。连接失联单独标为连接异常，不能表现为任务完成。

### 4.1 通用指针、点击与焦点行为

| 当前情形 | 输入/事件 | 设计结果 | 依据 |
| --- | --- | --- | --- |
| 总开关关闭 | 来源仍有任务 | 不显示岛，任务继续运行 | S；来源独立为 E |
| 无活动，空闲显示开启 | 无操作 | 显示宠物与问候 | S + P |
| 无活动，空闲显示关闭 | 无操作 | 隐藏岛窗口 | S + P |
| 空闲收起栏 | hover / 点击 | hover 不展开内容；点击工作台 | P；工作台目标为 E |
| 活动收起栏 | 鼠标进入 | 立即轻微形变；停留约 **300ms** 后展开 | P |
| 活动收起栏 | 300ms 前离开 | 取消本次 hover 展开 | P 逻辑还原，需原型逐项验证 |
| 活动收起栏 | 单击 | 切换展开状态 | P |
| 由 hover 打开的展开态 | 鼠标离开 | 约 **100ms** 后检查实际命中区域；确实离开且无保护条件时收起 | P |
| 展开态，输入焦点 / pin / 提交中 | 鼠标离开 | 保持当前内容，避免输入丢失与提交中跳走 | P |
| 展开态 | Esc | 收起并把焦点还给收起按钮；不等价于批准、拒绝或提交答案 | P |
| 鼠标浏览 | hover / 查看 | 不抢走原应用键盘焦点 | P |
| 输入答案 | 点击/聚焦输入 | 申请原生键盘焦点，固定当前请求 | P |
| 关闭 / 稍后 | 主动点击 | 解除当前 pin；请求是否仍待处理由来源决定 | P |

Esc 的收起与焦点返回已由静态逻辑确认；它在各输入场景下的草稿保留与编辑锁释放，需要随录屏单独核对。不能为了做原型自行把 Esc 扩展为清空草稿或拒绝来源请求。

### 4.2 各任务状态的主要动作

| 任务/请求状态 | 呈现与主动作 | 边界 |
| --- | --- | --- |
| 执行中 | 原有运行列表；点任务回原会话 | 不生成缺乏依据的进度百分比 |
| 等待回答，可在岛内回答 | 选择或输入 → 多题逐步前进 → 最后一题统一提交 | 最多 20 题且全部非多选；空白答案不能发送；20,000 字符上限 |
| 等待回答，超出岛能力或来源无回传 | 保留问题语义，主动作回原会话 | 不显示可输入但不能提交的假表单 |
| 等待权限，可轻量批准 | 预览描述、目录、命令；批准 / 拒绝 / 回原会话 | 有效请求、来源相应操作能力和通用轻交互边界同时满足 |
| 等待权限，不能岛内批准 | 提示在完整会话核对；回原会话批准 | **有效请求仍可拒绝**，前提是来源支持拒绝；不能用 `canApprove=false` 同时隐藏拒绝 |
| 权限仅可观察 | 展示请求与“前往处理” | 来源无双向能力时，批准与拒绝均不伪装成可执行 |
| 提交中 | 原卡片保留，相关动作锁定并显示处理反馈 | 单次用户动作只产生一次提交；收到来源回执后才改状态 |
| 提交失败 | 显示就地错误，允许重试或回原会话 | 保留已输入内容；不伪造成功 |
| 请求过期 | 保留被固定请求和草稿，显示过期提示；可回原会话 | 批准、拒绝、回答均禁用；不能把旧答案套到新请求 |
| 完成 | 新结果、摘要、时间、未读数与打开会话 | 沿用未读/清理规则，不擅加自动消失时长 |
| 失败 / 中断 | 分别显示原有语义，查看详情或关闭提示 | 单次工具出错不直接升级为整个任务失败 |

输入法组合输入期间，Enter 不提交。若来源明确给出自动跳过时间，沿用原有倒计时语法；没有时间就不补默认倒计时。多题前后切换、自由文本和“稍后”使用相同的按钮层级与密度，不引入新的对话式分支布局。

**轻量审批保持语义，不硬编码来源名称。** Qoder 当前仅在特定 Bash 请求满足字段、长度和内容条件时允许批准。通用层接收适配器归一化后的命令审批，Codex 的 `exec_command` 等不能仅因不叫 Bash 被排除。命令、工作目录、描述应能完整预览；来源自己的权限作用域与校验仍然保留。额外作用域按钮只有来源明确支持时才出现，首期不凭通用化需求新增“始终允许”。

### 4.3 pin、草稿与多屏

1. 用户进入问题输入后，固定来源、会话、轮次和请求标识。任务重新排序不应把正在输入的卡片换成其他请求。
2. 每块屏幕有自己的展开状态，但共用会话投影。**全局只允许一块屏幕取得编辑权**，不限于是否为同一条请求。
3. 另一屏尝试输入时，沿用“请先完成另一块屏幕上的输入。”的就地反馈；该屏仍可浏览，不抢占已有输入。
4. 原会话或另一操作入口处理请求后，当前保留的草稿进入过期态。提示使用“这个请求已结束。草稿仍保留，请打开会话查看最新状态。”的原有语义。
5. 关闭/稍后释放 pin；请求结束不产生自动批准或默认答案。编辑锁释放、窗口关闭和来源断线是独立事件，需要在原型记录中分别验证。
6. 首屏和第二屏提交后共用同一个请求回执；过期画面不能保留仍可点击的批准/拒绝按钮。

### 5.2 设置页（S + P）

用户截图参考尺寸为 1804 × 1282；这只是图像尺寸，不是已确认的应用逻辑视口。本轮结合安装包参数采用逻辑902×641、DPR 2做同尺寸对照；这不等于已读取原应用窗口的逻辑尺寸。对比时保留原图比例，再评估控件和文字大小。

保留顺序：`屏幕顶部` → 显示灵动岛 → 空闲时显示 → 在其他显示器上显示 → 触觉反馈 → 灵动岛大小 → 内置/外接预览 → 宽度 → 高度。恢复默认大小仍与尺寸标题同区，不另做醒目的独立主按钮。

视觉保留：白色页面和分组背景、细灰边框、大圆角容器、黑色条目标题、灰色说明、右侧低饱和绿色开关与滑杆、横向浅色分隔、两列淡灰预览底板。不得把这页改成深色控制台；黑色属于岛主体，设置页继续使用参考的浅色语法。

| 设置变量 | P 基线 | S 当前画面 |
| --- | --- | --- |
| 显示灵动岛 | 默认关 | 开 |
| 空闲时显示 | 默认开 | 开 |
| 在其他显示器上显示 | 默认关 | 关 |
| 触觉反馈 | 默认开 | 开 |
| 宽 / 高 | 默认 100% / 100% | 100% / 100% |
| 宽度范围 | 20%–130%，步长 5% | 截图不能证明范围 |
| 高度范围 | 75%–125%，步长 5%；受刘海下限约束 | 截图不能证明范围 |
| 恢复默认 | 同时回到 100% / 100% | 截图只证明入口存在 |

第一版不含独立悬浮宠物时，仅移除“可独立于悬浮宠物开启”这类失去对象的说明句；条目名称、布局与核心语义保持。连接管理使用同样的标题/说明/右侧操作关系，不复制本产品不存在的设置。

## 6. 原型与验收方式

### 6.1 先建立可重复的场景

使用固定测试事件覆盖：空闲、纯运行列表、三任务混合排序、单选问题、自由文本、多题、超范围问题、可批准权限、只能拒绝的复杂权限、仅观察权限、提交中、失败重试、过期草稿、完成、失败、中断。Qoder CN 与 Codex 使用同一批标题长度和请求内容，比较时只更换来源。

原型阶段用场景入口驱动状态，入口放在测试工具中；产品画面里不放“测试”“点击切场景”等制作控件。工作台和连接管理各做最小主流程，不以静态截图代替可点击的问答与过期处理。

### 6.2 视觉验收与交互验收分开

| 验收层 | 方法 | 通过标准 |
| --- | --- | --- |
| S 设置页 | 与用户原图等比例并排、叠图和局部放大 | 顺序、双预览、控件对齐、文字层级和留白结构一致；逐项记录差异 |
| P 岛静态场景 | 同一内容、同一缩放、同一屏幕条件取图 | 壳形、状态、文字层级、宠物占比、卡片宽高遵循变量表；未补原版画面的部分标为待核对 |
| P 时序 | 屏幕录制 + 事件时间戳 | hover 300ms / leave 100ms 逻辑可重复；动画不能用瞬时显隐替代 |
| P 焦点 | 从原编辑器开始完整走一遍 | 浏览不抢焦点，输入获得焦点，Esc 收起并归还焦点；不因离开丢失内容 |
| P 多屏 | 原生窗口在至少两块屏幕操作 | 展开各自独立；第二屏不能抢编辑；同一请求只产生一个有效决策 |
| E 最小延伸 | 两来源同名任务、不同连接能力 | 来源可辨；操作回到正确会话；只显示实际可执行的操作 |
| E 真实接入 | 来源发起 → 岛内处理 → 来源确认 | 真实回执闭环；测试事件通过不等于接入成功 |

对实际新增内容只问三件事：是否为多来源必需、是否放进了已有语法、是否打断原来的主动作。任何来源筛选、聊天、模型管理或额外导航扩展需另列需求，不顺手进入本基线。

### 6.3 必须逐项记录的交互用例

- hover 未满 300ms 离开、满 300ms 展开、进入展开区域后越过边缘、100ms 内返回。
- 点击打开、hover 打开分别离开；输入聚焦、pin 与提交中分别离开；Esc 从这些情形退出。
- 中文输入法组词时按 Enter；空答案、20,000 字符边界、多题最后统一提交。
- 不可批准但可拒绝、来源完全不支持回传、提交期间再次点击、失败后重试。
- 原应用先处理请求、请求被替换、同名任务重排；旧草稿保留且不能回答新请求。
- 第二屏输入锁冲突、第一屏关闭/稍后、请求结束、显示器拔插后的锁和草稿处理。
- 调整宽高只影响收起态；刘海高度下限；恢复默认；关闭空闲显示后无活动时隐藏。
- 连接断开和恢复不误报完成；来源应用退出后旧授权不能继续操作。
- 减少动态效果、长中文标题、窄可用屏幕、200% 可读性；原生全屏、Spaces、Stage Manager 另做实机项。
