# 来源应用与结束提示同步

灵宠岛 0.1.19 默认开启「回到应用后收起结束提示」。在支持应用级同步的来源停留约 1 秒后，岛上该应用已有的结束提示自动收起。自 0.1.24 起，已查看的结束提示同时退出任务总览；内部仍保留会话关联、结果状态和时间，后续有新活动时重新显示。也可在「屏幕顶部」关闭。自 0.1.30 起，停留期间新到达的结束提示同样处理：来源应用持续在前台约 1 秒后一并收起，不需要切走再切回。

## 同步范围

- 收起本轮结束、已完成、执行失败和已中断提示，不改写任务结果。
- 已更新到新轮次（重新运行、待回答、待批准）的任务继续提示，不被早先的停留确认消费。
- 停留期间新到达的结束提示，在该应用持续停留约 1 秒后一并收起；期间切走、锁屏或休眠则取消等待，回到该应用后重新计时。
- 运行中、仍有效的待回答和权限请求继续保留，不发送批准、拒绝或问题回答。过期请求由独立的过期清理退出顶部提示，内部保留关联信息和草稿，任务总览不再保留过期行。
- Qoder CN 桌面和 IDE 按真实来源独立处理。同一应用的多个结束提示会一起收起。
- Codex 连接插件 0.1.3 的 helper 从自身真实祖先确认桌面宿主。独立 Codex、ChatGPT 宿主分别处理。终端启动的内置 CLI 不因二进制位于应用包内就被认定为桌面来源。
- 旧版或无法确认归属的 Codex 消息、Qoder 来源待识别消息、远程消息、通用来源及交互预览不自动清除。更新插件后，新活动会刷新同一 Codex 会话的归属。

## 实现与边界

DeepSeek Harness 不参与上述应用级批量收起。点击它的提醒后，灵宠岛插件必须确认已选中并加载对应会话，才收起该条提醒；其他 DSH 任务仍保留。插件 0.4.0 起，直接在 DSH 打开对应会话也会同步：该会话须是唯一主视图、历史已加载、主面板为 Conversation，且窗口可见并持续获得焦点约 1 秒。切换会话、失焦、隐藏或打开其他面板会重新计时。持续查看会定期续报，因此在会话中等待结果时也能收起新到达的结束提醒。该行为沿用「返回来源应用后收起结束提示」开关。

查看确认只修改对应会话的本地未读状态，不更新结果、历史或任务活动时间。确认携带本次停留的起点，岛同时核对最新结果的来源时间与本机接收时间；停留期间有新事件到达，旧确认不能消费它，包括同时间戳或延迟送达的结果。运行中、待审批、待回答、远端和来源未确认的会话均保留。插件未更新、未就绪、目标不存在或跳转失败时，保留原有提醒。

普通 macOS WorkBuddy 5.9.3 支持逐会话同步。开启「回到应用后收起结束提示」时，岛按本地结束提醒的会话 ID 只读查询 `~/.workbuddy/workbuddy.db`。只有当前轮的已完成记录从未读变为已读，且结果版本、时间和记录归属仍匹配，才收起对应提醒。新轮次用自己的提问和完成记录重新建立基线。初次查询已读、归档、删除、未观测到完整转换或查询失败时保留提醒。WorkBuddy AI 和其他版本可继续通过岛内操作处理提醒。 [调研与实测记录](WorkBuddy逐会话已读替代方案调研-2026-11-05.md)

其他来源沿用用户选择的**应用级提示收起**。Codex 桌面内部有线程已读消息，目前公开 Hook 无法订阅。应用级同步仅使用系统前台通知和岛的本地提醒状态。

`SourceAttentionMonitor` 监听 `NSWorkspace.notificationCenter` 的应用激活和失活事件，并订阅会话发布。应用级同步进入应用时捕获事件版本，结束提示在前台停留期间到达则重新计时。1 秒后复核前台应用、开关、会话来源与事件版本。WorkBuddy 只在存在可核验的结束提醒时查询，数据库读取在后台任务执行。关开关、锁屏、休眠或退出会取消等待，重开后重新取样。

窗口层的悬停、收起、动画及审批通道不依赖该监听。监听不申请辅助功能或录屏权限。

2026-10-24 经 Context7 先解析 AppKit 库，再查询 Apple 官方文档，确认激活/失活通知必须注册到 `NSWorkspace.notificationCenter`，`applicationUserInfoKey` 对应 `NSRunningApplication`：

- [应用激活通知](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification)
- [应用失活通知](https://developer.apple.com/documentation/appkit/nsworkspace/diddeactivateapplicationnotification)

## 验证

`./scripts/verify-source-attention.sh` 通过隔离 SQLite、真实 AppModel 和 SourceAttentionMonitor 验证 WorkBuddy 按 ID 收起、同一轮生命周期事件、旧确认和旧数据库记录的防护、归档保留，以及应用前台状态与 WorkBuddy 已读判断的隔离。该脚本也覆盖 DSH 手动查看、其他来源、停留取消和请求保留。`node --test scripts/verify-dsh-plugin.mjs` 覆盖 DSH 插件，`verify-origins.sh` 核对来源身份，`verify-application.sh` 验证原有请求通道。
