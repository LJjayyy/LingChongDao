# 保持唤醒（含合盖）

灵宠岛 0.1.27 将功能范围与本机 NotchNotes 对齐，包含管理员授权及合盖防休眠。0.1.26 只有无权限的自动休眠断言，未覆盖合盖；此版本修正这个差异。

## 使用

工作台顶部咖啡杯、展开岛底部、菜单栏和「屏幕顶部 → 实用工具」控制同一状态。

1. 点击「保持唤醒（含合盖）」。macOS 会申请管理员授权，密码只在系统窗口中输入。
2. 授权并确认电源状态成功后显示「已开启（含合盖）」。等待授权期间显示等待状态并禁用重复切换，取消授权回到关闭。
3. 开启时阻止 Mac 休眠，包含合盖场景；开盖时的屏幕自动熄灭也会被阻止。收起岛显示咖啡杯，咖啡杯不计入任务数量。
4. 关闭开关后恢复开启前的电源状态。关闭工作台窗口时仍保持有效；退出应用会先等待恢复完成，恢复失败则保留应用与明确重试入口。
5. 每次启动不自动开启。若发现本应用上次未完成的可信恢复记录，会显示恢复提示，由用户明确操作申请恢复授权。

**锁屏与休眠不同。** 本功能保持任务运行，不更改 macOS 的锁屏密码或登录验证；开盖需要解锁不代表任务暂停。系统安全与硬件行为仍由 macOS 决定。

## 实现与恢复

参考 NotchNotes 的管理员 AppleScript 驻留守护和 `pmset -a disablesleep 1`。同时持有防止系统及屏幕自动休眠的 IOKit 断言，等管理员守护确认成功后才创建，并在关闭、启动回滚或退出时释放。

守护在更改前读取原值：原值为 0 时记录修改意图后开启，关闭时恢复为 0；原值已经为 1 时不覆盖，也不擅自恢复为 0。普通进程退出由独立守护检测并恢复。不同工具共享系统全局禁睡开关，不能把此开关当成具有独立所有权的引用计数。

管理员进程只向固定、不可被普通用户替换的 root 所有状态目录写入握手和恢复记录。客户端临时目录仅提供停止请求输入。恢复验证目录、记录归属与原值，只处理本应用可确认的记录；没有可信记录时不盲目重置全局设置。正常完成后清理记录，异常记录留待明确恢复。

程序监视实际守护存活状态，残留文件不会被当成“已开启”。启动失败回滚、授权取消、超时、部分资源释放失败均有状态和重试处理。

## 验证方法

- `./scripts/verify-clamshell-guard.sh`：假电源命令、假授权及离线 AppleScript 编译，覆盖原值、私有输入与可信状态树、修改与恢复、进程退出、取消、超时、残留恢复和不可信记录。
- `./scripts/verify-keep-awake.sh`：fake guard 与 fake IOKit，覆盖成功前不报开启、等待授权时退出、失败回滚、恢复失败保留状态、守护死亡和跨启动明确恢复。
- `./scripts/build-app.sh release`：完整应用及现有插件契约构建验证。
- 原生验收通过咖啡杯触发系统授权；授权必须由用户在系统窗口完成。读回 `SleepDisabled` 与本应用电源断言，在关闭和退出后验证恢复。不通过自动化输入密码，也不自动合盖或锁屏。

原生结果以交付的验证记录为准，不把 fake 测试或仅出现授权窗口当作实际合盖验收。

## 依据

- `<USER_HOME>/Documents/NotchNotes/Sources/NotchNotes/SystemSleepGuard.swift` 与 `AppSettingsStore.swift` 的本机参考实现。
- 本机 `/usr/share/man/man1/pmset.1`：修改参数需要 root，`-a` 表示所有供电模式。
- macOS 27 SDK `IOKit/pwr_mgt/IOPMLib.h`：自动休眠断言不会阻止合盖或手动睡眠，与强合盖机制有区别。
- [Apple QA1340](https://developer.apple.com/library/archive/qa/qa1340/_index.html)。Context7 已解析并检索 IOKit 文档，所返回条目不足以解释强合盖开关，最终使用当前 SDK、本机手册与参考源码核验实现。
