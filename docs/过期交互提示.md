# 过期交互提示

灵宠岛 0.1.20 修复过期审批仍反复占据顶部、标题仍写“需要你的批准”的问题。

## 根因

原实现保留过期请求对象以禁用旧按钮，但可见性、优先级和徽标只判断对象是否存在。于是一个已经无法从灵宠岛处理的请求仍被当作当前待审批，并且被应用级结束提示同步排除。

Codex 当前 Hook 的 PermissionRequest 还可能没有可和 PostToolUse 稳定对应的请求 ID；没有可靠关联时，不能由同会话任意工具完成事件推断该审批已经在来源处理。这个限制与本地过期提示清理分开处理。

## 规则

- 仍有效的审批、deny-only 审批及仅回来源确认的权限事件继续提示；不根据是否可在岛内允许来决定请求是否有效。
- 超时、断线或已过期输入不再占顶部数量或交互优先级，工作台保留请求对象、摘要及失效状态。
- 失效请求两种决策均禁用，通道返回来源常规处理，不代替用户批准或拒绝。
- 标题区分真正可回传的“需要你的批准”、状态提示“请在来源确认”和已失效的“岛内处理已结束”。审批过期说明不再提“草稿”。本地通道结束不等于来源审批已完成。
- 新活动可恢复运行；周期过期扫描不能把后续运行状态改回空闲。旧请求到期不能操作新请求。
- 已打开的问题草稿仍留在当前卡片，失效时释放输入锁，退出卡片后不重新作为待回答提示出现。

## 验证

`./scripts/verify-expired-requests.sh` 在实际 AppModel/SessionReducer 链路上验证可见性、历史和草稿保留、动作禁用、活跃请求保留、严格 ID 关联以及后续运行状态。修复前首项“An already expired approval never enters island attention”失败；修复后全部通过。已有核心过期测试改从 sessionsByID 检查历史对象及禁用状态，避免过滤后空值导致假通过。
