# WorkBuddy 普通对话 P0 修正与验收

日期：2026-11-01（Asia/Shanghai）。范围为普通 macOS WorkBuddy 客户端对话的信息同步与状态一致；不增加岛内回答、审批或任务控制。

## 结果

已在普通 WorkBuddy **5.9.3** 的专用真实客户端对话中验证：原生问题出现后显示待确认；超过 110 秒转为状态待核实并继续保留；从岛准确返回来源；回答后结束并同步实际回复摘要；同会话连续追问正常收口；用户停止生成后显示本轮结束及来源的 `Interrupted by user`，不误报成功。

前两轮普通回复与只读文件检查曾使用旧安装版；这些只证明源端操作及原有事件链，不计为新构建验收。后续已退出旧实例，直接启动工作区 app 可执行文件，并通过 lsof 核对实际加载路径，再完成新构建的完整等待与收口测试。

## 实机发现与修正

1. **原生等待开始信号是 Notification。** 原有六 Hook 漏掉了 `Notification(permission_prompt)`，导致原生选择题正在等答案时岛仍显示运行。本次增加第七项只读 Hook；不安装 PermissionRequest，不回传决定。
2. **问题工具的 PreToolUse 在回答后才到。** 实测在原生选择控件出现约 146 秒后，选择答案才收到 AskUserQuestion 的 Pre/Post。不能用这些执行事件推断等待开始。通知只显示“等待确认或回答”，不伪造精确请求。
3. **超时不等于来源已解决。** 本地 110 秒观察期到期后，问题或原生通知仍保留为“状态待核实”；短 socket 时限不压缩该观察期。无关工具、子任务和普通通知不能清除等待。
4. **收口保持保守。** 仅在通知固定模板明确指向 AskUserQuestion，且后续收到同名、带稳定调用 ID 的主工具事件时恢复运行；无法关联的只读通知等待新请求、明确终态或用户手动关闭。
5. **保留真实结果。** Stop 提供字符串回复时保留最多 600 字摘要，敏感字段回来源查看；保持“本轮结束”语义。已观察结果不再被 SessionEnd 或迟到子任务覆盖；SessionEnd 本身不制造未读成功。
6. **适配真实问题结构。** 支持 `tool_input.questions[]` 与只读选项标签，兼容旧字段；通知的 `title` 不覆盖任务标题。
7. **关联真实轮次。** 捕获到同轮 UserPromptSubmit/Notification/Pre/Post/Stop 的 generation_id 哈希一致；同会话新追问及下一轮取消分别变化。WorkBuddy 使用该真实字段作为轮次兼容入口，显式 turn 字段仍优先。

岛、列表、紧凑计数和无障碍描述区分“待处理”“状态待核实”和“新结果”；通知卡不显示岛内批准、拒绝或回答操作。

## 清理与范围

临时探针已从活动 WorkBuddy 配置及本轮含探针的备份中精确移除，保留正式七项 Hook 和其他用户配置。自动收起已通过界面恢复原值开启。最终安装版的只读文件、真实摘要及精确返回均再次通过；GUI 控制已结束。探针脚本、私有配置临时副本、元数据日志、临时材料和截图均已清理，专用测试对话保留供用户查看。

WorkBuddy AI、所有原生危险审批、云任务、失联恢复和任意并发权限请求不在本次实机覆盖范围；不把普通选择题验收扩展为这些能力已全部通过。工作区其他来源的独立修改均保留。
