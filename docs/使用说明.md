# 灵宠岛使用说明

[返回产品首页](../README.md)

你的 AI 灵宠工作台，独立运行于 macOS。顶部岛与交互以 Qoder CN 的灵动岛为基线，加入多个 AI 来源；工作台延展为老板鼠坐镇的暖纸色办公室。

## 下载与安装

支持 **macOS 14+、Apple Silicon（M 系列）Mac**。

1. 从本项目的 GitHub Releases 下载 `LingChongDao-版本-macOS-arm64.dmg`。
2. 打开 DMG，将「灵宠岛」拖入「Applications」，再从「应用程序」启动。
3. 在「连接的应用」安装所需来源插件，按来源要求审查、启用并重启，再开启新会话。

安装包包含老板鼠动画、应用图标及接入 helper，普通用户无需安装 Swift、Python 或 Node，也无需在灵宠岛填写模型 API Key。

应用与 [ClearZip](https://github.com/LJjayyy/ClearZip/releases/tag/v1.0.0) 一样采用 ad hoc 签名，尚未经过 Apple 公证。首次打开若被 macOS 拦截，请确认下载来源后，按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)处理。

开发者本地生成 DMG 可运行 `./scripts/package-dmg.sh`，产物位于 `dist/release/`；详见 [DMG 构建与发布](发布DMG.md)。

## 运行

从 `/Applications/灵宠岛.app` 启动；本地开发安装可运行 `./scripts/install-local.sh`。应用驻留菜单栏；打开工作台时显示老板鼠 Dock 图标，支持从 Dock 切回和恢复最小化窗口；关闭工作台后隐藏 Dock 图标，顶部灵宠岛继续运行。以 `--background` 启动时保持后台常驻，不显示工作台和 Dock 图标。菜单栏图标可以打开工作台、检查连接、显示灵宠岛和退出。支持 macOS 14 及以上；当前交付包在 Apple Silicon 上构建。

灵宠岛默认开启，可在「屏幕顶部」调整。收起态保留左侧来源宠物，右侧以并排彩色数量胶囊显示每种非零状态的会话数（运行绿、问题青、审批橙、失败红、结果蓝）；完整文字在展开态和无障碍描述中提供。运行与结果混合时同时显示绿色和蓝色数量，所有胶囊的真实数量之和对应可见会话总数；单项超过 99 时显示 99+。展开列表每行显示同色状态标签，移除重复应用名，任务超过三条时可滚动查看；来源身份仍保留在无障碍描述中。空闲时只显示默认灵宠「老板鼠」。默认宽度随宠物与数字所需空间收紧，刘海屏按实际摄像头区域预留安全空间，100% 即最小安全宽度。支持空闲问候、悬停展开、点击展开、需要处理时自动下拉提示（任务出现待批准、待回答、本轮结束、完成、失败或中断时，无需悬停自动下拉，只聚焦显示需要处理的那几条，运行中任务不在本次下拉内容里；8 秒无操作后收起，鼠标停在岛上时延后收起，自己点开或悬停展开仍显示全部）、输入后 Escape 收起、草稿保留、尺寸调整、多个显示器，以及 Force Touch 触觉反馈。在「任务总览 → 交互预览」可切换示例状态，示例不会执行命令，也不会替换真实任务。

展开后的宠物、任务摘要和时间组成整行点击区域，与「打开会话」按钮一致，点击会定位来源会话并收起岛；来源暂不支持会话入口时，按实际能力打开项目或应用。问题输入与批准、拒绝、关闭提示按钮仍各自独立操作。展开列表的任务行支持横向滑动清除（触控板双指轻扫或按住拖动，对齐 iOS 通知行与 macOS 通知中心）：行跟手移动并淡出，越过阈值或快速甩动后飞出、其余行弹性收拢，不足则回弹；运行中的任务也能滑走，同一会话有新事件时重新出现，实时待批准与待回答不会被滑掉。

任务总览只显示正在运行、有效待处理和未读结束提示。结束提示被成功打开、手动清除或通过来源应用前台同步收起后，直接退出列表。内部保留会话关联信息，同一会话有新的任务或结果时重新显示；运行中和有效待批准、待回答的任务不会因已查看而消失。工作台任务卡片与展开岛任务行一样支持双指轻扫或按住拖动横向清除（含卡死的运行中任务），悬停时卡片左上角出现 macOS 通知同款的灰色 ×，点击原地淡出并移除；实时待批准与待回答不显示 ×，滑动也会弹回。

岛内列表、展开卡片与工作台统一显示会话标题或本轮用户提问，缺少时回退到项目名，不再用「Qoder 会话 / Codex 会话」重复来源。已有标题与项目会在后续工具事件中保留，子任务不会覆盖主任务标题。首次收到的事件若不含标题、提问或有效项目目录，暂显「未命名任务」，新的提问到达后更新；不会为补标题扫描来源聊天历史。

默认开启「回到应用后收起结束提示」：进入来源应用并停留约 1 秒后，收起该应用已有的本轮结束、完成、失败和中断提示；停留期间新到达的结束提示也会在持续停留约 1 秒后一并收起，无需切走再切回。已查看或清除的结束提示也会从任务总览移除。Qoder CN 与 IDE 分别处理，Codex 按已核验的桌面宿主区分；终端或无法确认归属的消息保留。运行任务、待回答和权限请求不自动清除。可在「屏幕顶部」关闭。当前是应用级提醒同步，同一个应用的多条结束提示会一并收起，不代表来源报告了逐会话已读。详见 [来源应用与结束提示同步](来源应用与结束提示同步.md)。

“保持唤醒”默认关闭，可通过工作台顶部咖啡杯、展开岛底部、菜单栏或「屏幕顶部 → 实用工具」开启。功能与 NotchNotes 对齐：管理员授权后启用合盖防休眠，并保持屏幕与 Mac 唤醒；等待授权时显示等待状态，确认成功后才显示已开启。关闭或退出时等待恢复开启前的电源状态，原先已由其他工具启用的防休眠不会被直接关闭。开启状态、取消、失败和恢复状态在所有入口同步；异常遗留提供明确恢复入口。macOS 的锁屏验证设置保持原样。详见 `docs/保持唤醒.md`。

空闲时悬停约 0.28 秒，老板鼠会展开一段“突击查岗”：巡视、瞪眼指点，再吐槽一句全员摸鱼；戳它可换一句并再演一次。稳定悬停不会反复播放，短暂移出再回来也不重播，移开后自动收起；有任务到来则立即让位给任务。展开卡片提供工作台入口和原有咖啡杯。开启系统“减少动态效果”时直接显示静态表情与台词，不抢键盘焦点、不触发任务。

悬停展开使用连续弹簧，肩部、圆角、尺寸和首只宠物一起过渡；内容预先测量，稍后淡入，收回时内容快速淡出。快速移出、移回可打断并继续过渡。宿主画布保持固定高度，避免静置后的首次展开整岛向下跳动。遵循系统「减少动态效果」。具体调校与验证见 `docs/动效设计.md`。

## 接入 Qoder CN / IDE

在「连接的应用 → Qoder CN / IDE」用与 Codex 一致的插件卡片操作：**安装 / 更新插件**（未安装时显示「安装插件」，检测到新版本才显示「更新插件」）、**卸载插件**（卡片底部独立灰色垃圾桶图标，二次确认），以及卡片底部的「手动安装」胶囊（导出插件包）。**安装为 Qoder 原生插件**：灵宠岛自带一个 `.qoder-plugin` 包（`integrations/qoder-plugin`），复制到 `Application Support/LingChongDao/qoder-plugin` 后用 Qoder 自带 `qoderclicn plugins install <目录>` 装为 `lingchongdao-qoder@local`（离线），可在 Qoder 的插件管理中开关；同时清理旧版写进 `~/.qoder-cn/settings.json`（及 0.1.x `~/.qoder/settings.json`）的灵宠岛命令，避免重复上报。

CN 桌面端与 IDE 共用 `~/.qoder-cn` 的用户级插件；安装或更新后请重启 Qoder，再开启新会话。安装仍尊重 `QODERCN_CONFIG_DIR`、`QODERCN_CLI_HOME` 与 `QODERCN_CONFIG_DIR_NAME` 解析出的目录；早期误装到 `~/.qoder/settings.json` 的本应用命令仍可精确迁移。

## Codex：一键安装插件

Codex 接入统一使用「灵宠岛」插件（四个平台的插件展示名统一为「灵宠岛」）。打开「连接的应用 → Codex」，只有未安装时才显示「安装插件」，检测到随应用分发的新版本时才显示「更新插件」；卸载是卡片底部的灰色垃圾桶图标，需二次确认。应用自动放置完整插件、登记本地来源、调用 Codex CLI 安装并核对启用状态；成功后清理本应用精确管理的旧版直接 Hook，保留其他来源的 Hook。失败可重试，旧接入保留。

首次安装后在 Codex 的钩子审查界面确认「灵宠岛 · …」，再开启新会话验证。插件安装不等于信任，也不代表现有会话已重新加载。被禁用的插件需在 Codex 中启用；灵宠岛不自动信任或重启来源应用。

CLI 不支持安装时会说明原因，也可点卡片底部的「手动安装」胶囊导出完整插件包。插件附带 helper，无需用户安装 Python、Node、填写个人路径或额外开网络服务。源码、命令和说明见 `integrations/codex-plugin/`；安装实现与边界见 `docs/Codex插件与接入产品化.md`。

连接卡片默认显示来源应用的官方图标；来源应用启用宠物且素材可读取时，改用当前宠物。Qoder CN 读取独立的桌宠开关，Codex 读取桌宠显示设置；关闭后约两秒恢复应用图标。仅安装 IDE 时显示 IDE 图标。

## 接入 CodeBuddy CN / WorkBuddy

在「连接的应用」中分别预览、安装两款应用的六项同步命令，然后在来源检查 Hook 设置并开启新会话。卡片只有收到实际活动后才显示「已收到活动」，安装文件存在时显示「已安装，待验证」。每次改写保留其他配置和 Hook，并备份原文件；「断开」只移除灵宠岛管理的命令。

- CodeBuddy CN IDE：默认 `~/.codebuddy/settings.json`；同步会话开始、用户提问、工具开始/结果、本轮结束与会话结束。当前点击消息打开准确的 CodeBuddy CN 应用，暂不承诺选中具体聊天。
- WorkBuddy：默认 `~/.workbuddy/settings.json`，目录优先级为 `WORKBUDDY_CONFIG_DIR` → `CODEBUDDY_CONFIG_DIR` → 默认路径。本机桌面来源且会话 ID 为有效 UUID 时，点击消息使用 `workbuddy://chat/<session_id>` 定位已有任务；未知来源、远程或其他 ID 保留应用级回退。
- 两款应用先同步状态，问题回复与权限决定在来源处理。不会安装 `PermissionRequest` Hook，不会自动批准、拒绝或修改来源信任状态。官方应用图标用于两个新来源；尚无已验证的用户宠物读取契约。
- 同名会话按来源应用隔离。独立终端运行的包内 CLI 不会被认成 GUI 任务。WorkBuddy AI 的 home 是 `.workbuddy-ai`，本次不自动安装到该产品；已有可信来源事件可区分显示，但不套普通版任务链接。

引擎与配置证据、已验证能力及边界见 [Buddy 接入实施核验](Buddy接入实施核验.md)。来源应用仍可能要求审阅、信任或重启后加载；灵宠岛保留其正常流程。

## 接入 Claude Code

在「连接的应用 → Claude Code」点击 **安装插件 / 更新插件**，即可通过 Claude 官方 CLI 安装用户级灵宠岛插件；支持本机 Claude Code CLI、Claude App 的 **Code 本地会话**，以及本机 VS Code / Cursor / JetBrains 中的 Claude Code。没有单独安装 CLI 时，应用可检测 Claude App 下载的本地引擎；若尚未下载，请先在 Claude App 开启一次 Code 本地会话。插件可在 Claude 中禁用或卸载，也可从卡片底部「手动安装」导出完整本地市场包。

安装后请重启来源并开启新会话。同步会话开始、用户提交、工具开始与结果、错误、本轮停止、会话结束、子任务和通知；**完整预览的简单 Bash 和网页搜索可以在岛内「批准一次」或「拒绝」**，也可点「回 Claude 处理」。复杂请求只提供拒绝和回来源核对，普通问题在 Claude 回答。插件通过 PermissionRequest Hook 为每次请求生成独立审批 ID，支持并发请求排队；不修改长期允许规则，不读取 transcript 文件或注入上下文。Stop 只表示本轮停止。点击任务打开识别到的 Claude App、终端或 IDE，目前不承诺定位具体会话。

Claude App 的 Chat、Cowork、云端、SSH 和容器会话不在本版接入范围。来源从 Hook 进程祖先识别；缺少宿主证据时显示「来源待识别」。实现与本机验收见 [Claude Code 插件接入调研](Claude%20Code插件接入调研.md) 和 [插件说明](../integrations/claude-plugin/README.md)。

## 接入 ZCode

在「连接的应用 → ZCode」用与 Codex 一致的插件卡片操作：**安装 / 更新插件**（未安装时显示「安装插件」，检测到新版本才显示「更新插件」）、**卸载插件**（卡片底部独立灰色垃圾桶图标，二次确认），以及卡片底部的「手动安装」胶囊（导出插件包）。**安装为 ZCode 原生插件**：灵宠岛自带一个本地插件市场（`integrations/zcode-plugin`），安装时复制到 `Application Support/LingChongDao/zcode-plugin`，用 ZCode 自带 CLI 注册并安装 `lingchongdao-zcode@lingchongdao-local`（离线），可在 ZCode 的「插件管理 → 已安装」里看到并开关；同时清理旧版写入 `~/.zcode/cli/config.json` 的命令 Hook，避免重复上报。

同步会话开始、用户提问、工具开始/结果、工具失败与本轮结束；具备稳定请求 ID 的简单 Bash 权限可在岛内批准或拒绝，其余操作请回 ZCode 处理。守护模式下触发安全规则的危险命令审批（「仅允许这一次」类确认）不经过 Hook——ZCode 对这类一次性批准有意不派发 Hook——因此不会出现在岛上，请在 ZCode 内确认。安装或更新插件后请重启 ZCode，再开启新会话。ZCode 没有会话级深链，点击消息只打开应用；唯一的会话相邻路由 `zcode://workspace/open` 每次都会弹 ZCode 自家确认框，权衡后不采用。契约、证据与实测记录见 [ZCode 接入调研](ZCode接入调研.md)。

## 接入 DeepSeek Harness

在「连接的应用 → DeepSeek Harness」用与 Codex 一致的插件卡片操作：**安装 / 更新插件**（未安装时显示「安装插件」，检测到新版本才显示「更新插件」）、**卸载插件**（卡片底部独立灰色垃圾桶图标，二次确认），以及卡片底部的「手动安装」胶囊（导出插件包）。安装时把 helper 与组合包复制到 `Application Support/LingChongDao`，用应用自带的 `dsh` 以 `link:` 方式登记并选中到 `dsh.profile.bundles`（**离线**）。装好后它会以灵宠岛应用图标出现在 DeepSeek Harness 的「插件 → 已安装插件」里，可自行开关或卸载；不依赖 `dsh-hooks-claude-code` 等实验包，也不再向 profile patch 写 loader 行。

插件只观测：会话开始、用户提问、工具开始/结果、本轮结束、子任务；不注入上下文、不拦截工具、也不回答权限，权限请求仍在 DeepSeek Harness 里处理。安装后请完全退出并重启 DeepSeek Harness，再开启新会话验证。没有会话深链，点击消息只会打开应用；卡片上的「卸载插件」会取消组合包启用、移除 profile 依赖并删除本地副本。

契约、观测点与实测记录见 [DeepSeek Harness 接入调研](DeepSeekHarness接入调研.md) 与 [插件说明](../integrations/dsh-plugin/README.md)。

## 当前能力

- 同时显示 Qoder CN、Codex、Claude Code、ZCode、DeepSeek Harness、CodeBuddy CN、WorkBuddy 及通用 JSON 来源的任务活动；不同来源、主机、会话和线程分别识别。
- 问题、权限请求、失败/中断、完成、运行中的状态按优先级呈现；Stop 只表示本轮停止，不擅自推断成功。
- Codex 中明确确认当前回合使用人工审查、具有稳定请求 ID 且可完整预览的简单 Bash 请求，可在岛内单次批准或拒绝。「帮我审批」自动模式及无法确认审查者的请求立即交回 Codex，不生成岛内待审批；详见 [自动审批兼容](Codex自动审批兼容.md)。ZCode 中具有稳定请求 ID、可完整显示的简单 Bash 请求，以及 Claude 中可完整预览的 Bash / 网页搜索请求，保留岛内单次批准或拒绝。复杂请求可拒绝或返回来源确认。Qoder 正式插件只同步等待权限状态，点击消息回 Qoder 确认，不提供岛内审批。
- Codex 的权限事件缺少可用请求 ID 时只作为「来源权限检查」更新摘要，不生成橙色待确认或审批倒计时；也不改变运行、结束或已有真实审批的状态。有效请求 ID 对应的审批继续保留。详见 [权限观察误报修复](Codex权限观察误报修复.md)。
- 超时、连接中断、过期或不匹配的响应会回到来源工具处理，不会自动批准。 已失效的审批或问题自动退出顶部提示，内部保留会话关联及已提交到草稿中的输入；仅需回来源确认的有效请求仍会提示。
- 当前 Hook 通道不支持通用问题回复；真实问题需打开来源应用回答。输入、选项和草稿交互可在预览中体验。
- Qoder CN 与 Qoder CN IDE 共用 Hook 接入。每条新消息通过 Hook 调用进程的应用身份区分来源，分别显示来源名称，并分别打开桌面端或 IDE；相同会话 ID 和审批 ID 也分开处理。独立共享后台等无法核验来源时显示「来源待识别」，点击后给出提示。
- 点击消息或「打开会话」时，Codex、Qoder CN 桌面端与已核验的本机 WorkBuddy 桌面根任务会携带当前会话 ID 定位对应任务，并明确指定目标应用，避免 Qoder 桌面端/IDE 的协议冲突。Qoder CN 的定时任务等智能体会话不在桌面聊天列表内，深链会被来源拒绝报错；这类会话（cwd 位于 `Documents/Qoder/<日期>/<短 ID>` 任务工作区）自动降级为「打开应用」，不误报错误。Qoder CN IDE 当前显示「打开项目」，打开已存在的本机项目目录；尚不能定位该项目中的某条聊天。缺少有效 ID、远程来源或不支持的宿主显示「打开应用」。跳转投递失败会保留未读提示并说明原因。不会扫描私人聊天历史，预览也不会打开虚构会话。

灵宠岛和任务列表按任务来源读取当前宠物：Qoder CN 支持内置宠物、Petdex 缓存与本地宠物；Codex 支持内置、本地自定义宠物，以及能映射到本地素材的云端选择。来源中切换宠物后，约两秒内自动刷新。动态图随运行、等待、完成与失败状态变化，并跟随系统「减少动态效果」。没有可见会话或尚未连接应用时，默认显示「老板鼠」。老板鼠会低频眨眼、偶尔瞪眼巡视；鼠标靠近时抬眼，点击工作台中的老板鼠会演出蓄力、抬指、碎碎念和收手，并轮换打工人台词。表演按时间逐帧播放，动作首尾回正，连续点击最多接一轮续播，避免中途重置或堆积。这些互动只改变角色表现，不控制任务。系统开启「减少动态效果」时停止自动动作及缩放旋转，保留静态交互反馈。Qoder CN IDE 暂无可核验的宠物读取通道，显示 IDE 自身图标。

读取仅在本机进行，不修改来源配置，不把来源宠物素材放进发行包。无法读取、未知素材格式或没有本地素材的云端宠物会显示来源应用图标。Codex 云端选择使用已迁移的本地素材，不保证与云端最新版本完全一致。

尚未实现自有会话服务、Codex app-server 问题回传、开机启动、更新器和发行公证。

## 名称与升级

应用与文档统一称「灵宠岛」；工程目录为 `灵宠岛`，Swift 主程序为 `LingChongDao`，Hook 工具为 `lingchongdao-hook`。升级会迁移原有设置与连接数据，旧命令通过兼容路径继续连接；在连接页预览并安装修复后会改用新路径。Codex 对更新后的命令可能要求重新审查，应用不会代替用户信任。详细对应关系与兼容范围见 [名称与兼容迁移](名称与兼容迁移.md)。

## 开发与验证

使用 Swift / SwiftUI / AppKit，无第三方运行依赖。源码构建需要 Apple Silicon Mac、Swift 6 工具链（Xcode 或相应 Command Line Tools）和 Python 3；这些是开发要求，DMG 用户无需安装。

```sh
python3 scripts/verify-public-source.py
./scripts/build-app.sh release
./scripts/verify-all.sh
./scripts/package-dmg.sh --no-build
# 可选：退出当前版本后，将开发产物安装到“应用程序”
./scripts/install-local.sh --no-build
```

`verify-all.sh` 串行运行 24 项隔离验证，保留各脚本自己的解释器；动效与布局检查需要活动的 macOS 图形会话。默认验证只使用私有临时目录、合成素材与隔离偏好设置，不安装真实来源 Hook；需真实 Claude CLI 的验证和 `--live` 宠物读取为可选项，详见 [贡献指南](../CONTRIBUTING.md)。无需完整 Xcode 即可运行默认验证，有完整 Xcode 时还可运行 `swift test`。

```sh
# 应用运行后：检查本地桥接
"/Applications/灵宠岛.app/Contents/MacOS/lingchongdao-hook" --ping
# 注入示例活动；不会执行其中展示的命令
"/Applications/灵宠岛.app/Contents/MacOS/lingchongdao-hook" --provider generic --send-fixture examples/running.json
# 审批与问答交互演示：在工作台「任务总览 → 交互预览」选择对应状态。
# examples/approval.json 是原始协议样例，缺少真实回合审查元数据时会安全回退，不能用于交互审批演示。
```

构建中的应用位于 `dist/build.noindex/灵宠岛.app`，DMG 和 `SHA256SUMS.txt` 位于 `dist/release/`，回滚副本位于 `dist/rollback.noindex/`，避免开发产物被系统搜索重复收录。只需 App 时可运行 `./scripts/build-app.sh release`，已有完整 App 时可运行 `./scripts/package-dmg.sh --no-build`。正式入口固定为 `/Applications/灵宠岛.app`。默认构建使用仓库内的老板鼠动画、应用图标和插件标识，无需额外下载素材。修改角色原图后可用 `./scripts/build-icon.sh` 重新生成各档应用图标。每次打包都会重建资源目录，避免遗留旧资源。旧参数 `--with-local-artwork` 仍可使用，与默认构建相同。

实现分层：`IslandCore` 负责状态与 Unix Socket；`IslandConnections` 负责配置检测、预览、合并和备份；`IslandPets` 负责只读宠物选择与本地素材解析；`LingChongDao` 负责工作台与每块屏幕上的非激活浮窗；`lingchongdao-hook` 负责将来源 Hook 转为本地事件并等待匹配响应。

参见 `docs/CORE-CONTRACT.md`、`docs/WINDOWS.md`、`docs/动效设计.md`、`docs/UIUX设计基线.md`、`docs/调研与产品方案.md`。

会话定位入口及版本边界见 [Codex 会话跳转调研](Codex会话跳转调研.md) 与 [Qoder 会话跳转调研](Qoder会话跳转调研.md)。系统确认链接已投递不等于来源确认页面已加载；来源账户变化、会话被删除或不在本机列表时，来源仍可能拒绝打开。当前定位到会话，不承诺滚动到某一条消息。
