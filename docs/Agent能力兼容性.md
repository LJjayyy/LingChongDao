# Agent 能力兼容性

[返回产品首页](../README.md) · [使用说明](使用说明.md)

灵宠岛对不同 Agent 的接入深度不同。**收到生命周期 Hook，不代表能完整同步原生待确认状态，也不代表可以在岛内审批。** 选择来源和排查状态差异时，以具体能力及其验证范围为准。

更新日期：**2026-11-01**。基础实现基线：仓库提交 `43df4f1`，WorkBuddy 更新以本次 P0 验收记录为准。本表描述灵宠岛当前接入；上游版本及验收范围见下文，不自动覆盖后续版本或同品牌的其他宿主。

## 状态与交互

“支持”表示当前已有实现；“受限”表示仅覆盖注明条件；“未接入”表示当前连接不提供该能力。实机、原生运行时和离线验证分别记录，不能互相替代。

| Agent 与宿主 | 生命周期与工具活动 | 原生审批等待同步 | 岛内批准或拒绝 | 问题等待与答复 |
| --- | --- | --- | --- | --- |
| Codex 本地会话 | 支持 | 受限：明确为当前人工审批才建卡；自动审查或未知模式交回来源 | 受限：可完整预览的简单 Bash 可批准一次；复杂请求仅拒绝或回来源 | 支持同步、异步问题等待；回来源回答 |
| Qoder CN 桌面 | 支持 | 受限：只读提示；部分收口依赖工具结果或回合结束 | 已撤回，全部回来源 | 未专项接入；回来源回答 |
| Qoder CN IDE | 支持 | 受限：沿用 Qoder 只读路径；桌面验收不能代替 IDE 验收 | 已撤回，全部回来源 | 未专项接入；回来源回答 |
| Claude Code 本地会话 | 支持 | 受限：活跃权限请求与只读通知；来源拒绝后可能缺少收口事件 | 受限：简单 Bash、WebSearch 可批准一次；复杂请求仅拒绝或回来源 | 条件识别问答工具及稳定请求 ID；回来源回答 |
| ZCode 桌面 | 支持 | 受限：只能观察已上报的 PermissionRequest；原生护栏确认有漏报 | 受限：简单 Bash 路径已实现，桌面审批仍待完整验收 | 未专项接入；回来源回答 |
| DeepSeek Harness 桌面 | 支持，含已接入的子任务事件 | 未接入 | 未接入 | 未接入；回来源回答 |
| CodeBuddy CN IDE | 支持 | **未实现完整同步，实测不可行，暂不做** | 未接入 | 条件识别问答工具及稳定请求 ID；原生覆盖待验收，回来源回答 |
| WorkBuddy 桌面 | 支持 | 受限：原生 permission_prompt 只读待确认，不承诺所有审批路径 | 未接入 | 5.9.3 原生选择题已实测；110 秒后保留状态待核实，回来源回答 |

所有当前接入的真实问题均由来源接收答案，**没有岛内问答回传**。Claude Code、CodeBuddy 的问答识别依赖工具名和稳定调用 ID。WorkBuddy 原生选择题可先通过只读通知显示待确认，已明确绑定的问题工具执行后收口；解析器能处理某类输入，不等于来源会在所有原生提问路径发出该输入。

生命周期也有边界：`Stop` 只表示本轮响应结束，不等于业务成功；缺少明确错误、取消或交互结束事件时，不能凭安静时长或命令关键词补出真实状态。超时和手动关闭提示只清理岛端提示，不代表用户已在来源批准、拒绝或回答。

## 安装与返回来源

| Agent 与宿主 | 当前连接入口 | 点击任务时的能力 |
| --- | --- | --- |
| Codex | 官方本地市场与原生插件，经 CLI 安装、启用 | 本地、正确应用身份及有效线程 UUID 时使用 `codex://threads/…`；否则打开应用 |
| Qoder CN 桌面 | 原生 `.qoder-plugin`，经 qoderclicn 安装 | 普通聊天可使用 `qoder-cn://chat/open`；已识别的计划任务等运行目录降级为打开应用 |
| Qoder CN IDE | 共享 Qoder CN 用户插件连接 | 打开有效的本地项目目录；不承诺定位到具体聊天 |
| Claude Code | 官方本地市场与原生插件 | 激活实际宿主应用、IDE 或终端；不定位具体会话 |
| ZCode | 原生 `.zcode-plugin` 与用户级本地市场 | 打开应用；逐次弹确认的工作区跳转已撤回 |
| DeepSeek Harness | 原生 bundle，经官方桌面 profile 的插件入口注册 | 经灵宠岛插件定位对应会话；收到选中且加载完成回执后只收起目标提醒，失败保留 |
| CodeBuddy CN IDE | 用户配置中的官方 Hooks，安装六类生命周期事件 | 打开应用 |
| WorkBuddy 桌面 | 用户配置中的官方 Hooks，安装七类事件，含 Notification | 正确应用身份及有效会话 UUID 时使用 `workbuddy://chat/…`；否则打开应用 |

插件已写入配置不等于连接已经运行。来源要求的审查、信任、启用、重启或新建会话仍须完成；以实际收到来源事件为运行验证。安装和卸载操作见[使用说明](使用说明.md)。

会话路由受本地来源、应用 bundle 标识和 ID 校验约束。应用文件名不能替代身份判断：文件名为 `ChatGPT.app` 的已验证安装实际可为 `com.openai.codex`，旧 `com.openai.chat` 不因此获得相同路由能力。系统接受打开请求，也不等于来源已显示正确会话或定位到具体消息。

Codex 与 Qoder CN 桌面另有读取本地宠物选择的兼容实现，需来源已开启且本地资源可读；它不是各 Agent 通用的官方宠物 API。其他来源及 Qoder IDE 使用应用图标。DSH 通过插件回执按会话收起提醒；其他来源返回应用后自动收起结束提示仍是应用级行为，不证明某条会话已读，也不会因此清除运行中或有效待处理状态，见[来源应用与结束提示同步](来源应用与结束提示同步.md)。

## 已验证版本与已知限制

下列版本是已有验证记录的基线，不是最低支持版本或上游最新版本。历史调研中的实验能力如已撤回，以本表和对应记录的最终结论为准。

- **Codex**：原生插件安装验证使用 CLI `0.163.0-alpha.11.2`；审批和同步、异步问答验证使用 `0.164.0-alpha.11.1` 的真实 CLI / App Server 与隔离模型响应服务，岛端使用实际应用交互。它们不能代替完整 Codex 桌面聊天界面验收。会话跳转已有静态与离线验证，未据此承诺桌面端全流程通过。见[插件接入](Codex插件与接入产品化.md)、[岛内审批](Codex岛内审批接入.md)、[问答等待](Codex问答等待状态修复.md)、[会话跳转](Codex会话跳转调研.md)。
- **Codex 自动审查**：`PermissionRequest` 先于自动审查，不足以证明正在等用户。当前实现只在当前会话、回合明确为 `approvals_reviewer=user` 时提供岛内审批；`auto_review`、缺失或未知值立即交回来源。审查者识别使用有界读取的回合元数据作为保守显示兼容提示，**该记录格式不是稳定官方接口**，不能宣传成纯稳定 Hook 字段能力，见[自动审批兼容](Codex自动审批兼容.md)。
- **Qoder CN**：桌面 `0.4.11`、qoderclicn `1.1.76` 已做原生权限确认及来源拒绝后的状态验收。岛内允许、拒绝曾触发来源回合收尾异常，已在灵宠岛 `0.1.38`、Qoder 插件 `0.1.2` 撤回；现行路径只读、不阻塞来源。缺少逐交互结束事件时不能保证完整双向同步。IDE `1.36.0` 的项目返回入口有静态调查，不能继承桌面审批验收结果。见[权限状态验收与撤回](Qoder岛内审批实机验收.md)、[接入修复](Qoder-CN接入修复.md)、[会话跳转](Qoder会话跳转调研.md)。
- **Claude Code**：Claude App `3.6556.2`、本地引擎 `2.1.304` 已验证岛内 WebSearch 批准、拒绝、不产生持久授权及回来源行为。来源原生拒绝后存在未发完整收口事件的路径，只读提示不能保证逐请求即时结束。覆盖范围是本地 CLI、Claude App 的 Code 本地会话及已接入的 VS Code、Cursor、JetBrains 宿主；不扩展到普通 Chat、Cowork、云端、SSH 或容器，也不把 App 验收算作所有宿主均已实测。见[Claude Code 插件接入](Claude%20Code插件接入调研.md)。
- **ZCode**：桌面 `3.16.3`、内置 CLI `0.17.0` 已验证原生插件与基础生命周期；简单 Bash 审批实现和离线检查不能替代完整桌面审批验收。用户实机确认原生危险命令“仅允许这一次”路径未上报对应 Hook，因而不能完整同步等待；不通过内部 IPC 补齐。见[ZCode 接入](ZCode接入调研.md)。
- **DeepSeek Harness**：`0.2.1-rc.2` 已在隔离 profile 中通过真实原生任务验证 bundle 生命周期；`0.2.1-rc.5` 的官方隔离客户端已验证插件及生产 Swift 导航客户端按 A/B 会话 ID 切换，GUI 使用合成空白会话，不代表用户已完成模型任务的非空历史验收。完成提醒与回执边界另有生产 AppModel 回归。不回传权限决定。升级后须核对 profile 的插件启用状态，见[DeepSeek Harness 接入](DeepSeekHarness接入调研.md)。
- **CodeBuddy CN**：`4.12.2 / Craft / Auto` 已在真实 IDE 中完成五组、23 条 Hook 输入的验证。原生危险确认可早于 `PreToolUse`；官方 `permissionDecision: ask` 能发起确认，但批准后缺少及时恢复运行的事件，可能一直等到长命令的 `PostToolUse`。**不新增状态同步实现、不做岛内审批，等待官方更新后复查**。IDE 与 CLI 的事件能力不能混用，完整基线见[原生审批状态同步结论](CodeBuddy危险命令等待状态调研.md)。
- **WorkBuddy**：普通桌面 `5.9.3` 已实测专用普通对话、只读文件、原生选择题、等待超过 110 秒、准确返回、来源回答、真实回复摘要、连续追问和用户停止生成。Native 问题在回答前发 Notification，回答后才发 AskUserQuestion 的 Pre/Post；不将该结果扩展为所有审批路径已验证。WorkBuddy AI 仍仅独立宿主识别，不自动安装普通版配置或套其会话路由。见[普通对话 P0 验收](WorkBuddy普通对话P0验收-2026-11-01.md)、[Buddy 接入核验](Buddy接入实施核验.md)。

开发用 `generic` JSON 入口只代表灵宠岛可接收标准事件，不代表另一个 Agent 已完成官方接入或权限回传认证。

## 更新与复查规则

新增能力以官方公开支持的目标产品、宿主和版本为前提，再完成实现与验证。不通过界面抓取、修改来源安装包、内部 IPC、伪造事件或猜测状态填补缺失能力；官方不足以实现时保留限制。

每次来源升级或修改连接时，按受影响能力更新本表及对应验证记录：

1. 记录来源版本、宿主、灵宠岛及插件版本、验证日期、官方依据和验证方式。
2. 分别核对普通运行、等待开始、批准后长命令执行、拒绝、跳过与取消；确认运行恢复不依赖命令结束，结束不误报业务成功。
3. 核对稳定会话及请求关联，覆盖并发、重复、迟到事件、重启与失联；缺失信号不得由其他会话的活动代替。
4. 核对原生权限策略与一次性决定语义；超时、未知格式或不支持的请求交回来源，不新增持久允许规则。
5. 只有实机覆盖的范围才标记实机通过；CLI、隔离 App Server、静态分析和回放分别注明。上游发布新事件或新增 `ask` 输出本身不算验收通过。
