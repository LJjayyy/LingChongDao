## 发现

### Medium：当前 app 含开发者 home 和工作区路径，阻塞直接分发此包

位置：`dist/build.noindex/灵宠岛.app/Contents/MacOS/LingChongDao`、`lingchongdao-hook`；主程序扫描命中 124 处、helper 40 处用户目录字符串，内嵌 Codex 插件 helper 同样存在。没有在报告回显真实路径。

原因：该包为之前客户端验证使用的 debug 构建。`scripts/build-app.sh` 默认 debug，直接复制编译二进制；`scripts/package-dmg.sh --no-build` 仅核对身份、架构和签名，不验证二进制是否含本机路径。现有源码检查排除 dist，因此源码预检通过不能证明附件清洁。

建议：发布使用干净环境的 release 构建，扫描 app 两个可执行文件及所有插件内 helper，确认无真实 home/工作区路径；若仍有则使用编译路径映射并复查。之后重新打包并检查实际 DMG 内容和校验值。不要发布当前调试包。GitHub 发布工作流已有显式 release 构建，因此该项不是断言线上工作流必然泄露；本轮未运行线上工作流。

### Medium：Git 可达历史对象仍有早期私人目录路径

范围纠正：逐引用复查确认 main、origin/main、v0.1.40 的 284 个 blob 无真实 home 命中；以下对象来自 5 个本地 Codex 快照树引用，不是已确认的公开提交历史泄露。处理后当前所有引用可达的 346 个 blob 均无真实 home 命中，无需改写公开历史或强推。

本地 `git rev-list --objects --all` 枚举的文件对象中，以下历史内容仍可读到真实本机目录：

- 早期 `docs/CodeBuddy-CN与WorkBuddy接入调研.md`、`docs/保持唤醒.md`。
- `docs/evidence/application-verification.log`、`core-verification.log`、`qoder-path-regression.log` 的旧对象。
- 早期 `promo/2026-10-29/` 中的脚本、生产计划、字体 CSS、字体下载标记和预览 HTML 对象。

示例对象短 ID（不含敏感值）：`c33d5b44f4`、`f8df1ae079`、`2f8382967e`、`701ce8d6c3`、`437b0f191b`。`rev-list --objects` 的路径是对象名称提示，不保证对应 HEAD 文件版本；以上不代表当前候选文件仍有相同内容。

这是历史隐私问题，不是已确认的密钥泄露。当前忽略规则和文档脱敏不能移除 Git 可达对象。是否这些对象也存在于远端，未联网或 fetch 核对，不能断言其已公开或从未公开。建议先确定此次拟推送引用及远端范围；若要求清理，先备份并形成明确历史重写方案。历史重写和强推不在本轮执行。
