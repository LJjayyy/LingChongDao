# WorkBuddy 官方开放能力调研

调研时间：2026-11-01（Asia/Shanghai）。范围为官方公开文档；没有注册应用、获取用户令牌、调用真实业务接口、安装插件或改变 WorkBuddy 配置。本文供灵宠岛后续产品取舍使用，不把文档声明视为本机端到端验证。

## 结论

WorkBuddy 有三种需要分别设计的接入方式：本机插件/Hook、取得用户授权后的开放 API、第三方应用分享。它们的适用范围不同。对当前桌面任务的伴随体验，应继续以已验证的本地事件为基础；开放平台适合独立的本地助理入口或云任务功能，不能直接当作所有桌面会话的控制接口。分享能力已有公开协议，适合把内容送入 WorkBuddy 输入区，但不会自动提交，也不等于跳回已有任务。

本轮使用 Context7 查询当前资料，再复查官方原始页面。Context7 命中官方 WorkBuddy 文档库，但返回内容不足以支持具体 API 契约，以下结论以逐项查阅的官方页面为准。

## 官方能力与边界

| 能力 | 已公开的支持范围 | 对灵宠岛的含义 |
| --- | --- | --- |
| 插件 | Skill、MCP、Hook、Agent、Rule；插件市场安装和管理、添加第三方市场 | 有官方分发方向；仍需验证第三方 Hook 插件在目标桌面版本的安装及触发 |
| 本地助理 | 查在线、发消息、分页/增量读取历史；有问答/审批回复消息类型 | 可研究轻量输入与回复；没有据此证明能选择任意桌面会话 |
| 云任务 | 创建、列表和详情；状态、ACP 连接信息 | 可另做云任务卡；不能冒充本机 Hook 会话 |
| 云端 ACP | SSE 接收、JSON-RPC 发送；更新、请求用户参与和轮次结束 | 可做有正式双向协议的交互；前提是云端任务和授权接入 |
| 云会话产物 | REST 获取历史，SSE 推增量 | 可做完成后的结果入口与断线恢复 |
| 第三方分享 | PC 端签名链接预填输入，用户检查发送 | 适合“交给 WorkBuddy”；不能标成“已开始执行” |
| 连接器 | MCP + Skill 或 CLI + Skill；本地 stdio 可用 | 可让 WorkBuddy 主动调用灵宠岛工具；不能替代必达的生命周期事件 |
| Buddy 应用 | 在 WorkBuddy 内封装垂直工作台 | 是另一种产品形态，不是灵宠岛原生 macOS 窗口的通用宿主 SDK |

来源：[插件系统](https://www.workbuddy.cn/docs/workbuddy/Plugins)、[插件管理](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Plug-In)、[Open API](https://open.workbuddy.cn/docs/openapi)、[第三方应用](https://open.workbuddy.cn/docs/third-party-app)、[连接器](https://open.workbuddy.cn/docs/connector)、[Buddy 应用](https://open.workbuddy.cn/docs/buddy-app)。

## 开放 API 不能混淆的两条路径

### 本地助理路径

公开路径为 `/openapi/v2/localassistant` 和 `/openapi/v2/localassistant/message`。消息读取使用 `message_id` 增量游标；发送消息的请求没有公开的目标 `sessionId`/`taskId` 参数。`permission_response` 要对应下行的 `requestId`，详细示例集中于问卷答案。因此，文档不足以保证能从岛上追问、审批或停止用户正在看的任意桌面任务。[官方接口](https://open.workbuddy.cn/docs/openapi#本地助理-api)

产品建议：如后续接入，先将它明确设计为“本地助理”入口，以独立身份展示在线/离线、发送中、等待回复与授权失效。发送成功只表示消息已接收，不能显示为任务完成。不要用账户级在线状态覆盖某个具体会话的活动状态。

### 云任务与 ACP 路径

`/openapi/v2/tasks` 提供任务创建、列表和详情；详情返回可用于云端 ACP 的连接信息。ACP 的更新、权限请求、轮次结束及产物增量，均有公开说明；产物可组合全量读取与增量订阅恢复状态。这里描述的是云端会话，`pending` 也不专指审批。[官方云任务与 ACP](https://open.workbuddy.cn/docs/openapi#云端任务-api)

产品建议：适合后续提供单独的“WorkBuddy 云任务”来源。以真实的轮次结束/失败/取消区分结果，以实际请求驱动问答交互；不要因为长时间无消息就推断任务完成或需要批准。断线后先恢复已有任务，避免把重连实现成新建任务。完成卡可以展示产物入口；文件可打开、是否仍可访问应与任务状态分别判断。

### 注册和运行成本

开放平台要求注册应用、申请对应权限并完成用户授权；应用类型的可申请范围不同。官方要求应用密钥保存在服务端。因而，灵宠岛不能仅在原生客户端增加一段 HTTP 调用就宣称完成正式接入；还需要先确认平台接受的应用类型、审核与服务端方案。[应用注册、权限与认证](https://open.workbuddy.cn/docs/third-party-app#硬件接入与积分兑换)

产品建议：保留无需账号的现有桌面联动作为基本体验。只有用户主动开启云端/本地助理功能时，才引入授权与相应连接状态；不要让已有用户为了继续观察本机任务被迫登录开放平台。

## 第三方分享：已公开，但属于输入交接

官方已发布 PC 分享开发说明：WorkBuddy 5.8.0+，通过 `https://workbuddy.cn/app/open-deeplink` 携带签名包；当前场景为 `newTask`，可承载多种内容块。它是输入区预填，用户仍需发送；已有新任务草稿可能被覆盖。接入需要企业认证、应用审核及服务端私钥。[分享能力与 PC 开发手册](https://open.workbuddy.cn/docs/third-party-app#分享能力接入)

产品建议：可做“把选中文本/文件交给 WorkBuddy”，先展示将交接的内容，再打开官方入口。完成提示应表达为“已打开 WorkBuddy，请检查后发送”。这是扩展任务入口，不应替代“回到当前任务”。是否需要这种能力，应结合灵宠岛是否承担快捷输入或文件拖入任务来判断；如果岛只是状态入口，优先级低于状态准确性。

本轮仍未找到可直接用于任意现有桌面任务的、包含完整参数和版本承诺的公开导航路由。旧更新日志中的“任务/项目/待办直达”不等于外部开发者已获得稳定参数契约。当前 bundle 激活回退仍有必要。

## 反向联动的选择

[连接器文档](https://open.workbuddy.cn/docs/connector) 明确支持本地 stdio MCP，并提供版本边界与凭证模式。由此可以研究让 WorkBuddy 调用“更新当前活动描述”“登记产物入口”“展示提醒”等本地工具。但调用是否发生取决于 AI 与任务流程，不能替代状态机依赖的 Hook。初期宜只提供语义明确、影响小的工具，并保留确定性事件作为运行状态来源。

[Buddy 应用](https://open.workbuddy.cn/docs/buddy-app) 是 WorkBuddy 内部工作台形态。即便其自定义页面存在 JS 能力，也不能把仅限其页面环境的 SDK 当作原生灵宠岛的桌面会话 SDK；若未来做内嵌小组件，应单独确定产品目标与宿主约束。

## 值得对应的源端体验

官方[任务管理](https://www.workbuddy.cn/docs/workbuddy/Task-Management)把执行、完成未读、失败、待确认作为可区分的用户状态；[系统设置](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)介绍任务相关系统通知和点击返回。

产品建议：岛上应优先突出需要用户参与和失败的任务，完成提醒保持轻量；多会话时只聚合有依据的状态。与 WorkBuddy 系统通知同时开启时，提供易理解的提醒控制，减少同一结果被重复打扰。是否具备对应状态数据，必须逐项查本机事件，不以官方 UI 有该状态推断 Hook 一定会发出。

## 实施前需向官方核实的文档问题

1. **令牌有效期不一致。** 应用接入说明写 access token 为 24 小时，API 示例的 `expires_in` 为 3600。实现应以响应字段安排刷新，不把任何示例时长写死。
2. **分享签名说明不一致。** 密钥说明提到 PSS，PC 快速开始却使用 `RSA_PKCS1_PADDING`。正式接入前必须核实实际验签算法，不能凭示例任选。
3. **产物地址推导不一致。** API 任务样例返回 ACP 网关 `/sessions/{id}`，产物章节则说明从直连沙箱 `/acp` 地址去尾得到基础地址。需要平台明确两类地址的转换/返回字段；不能对网关 URL 机械删后缀。
4. **本地助理问卷与工具审批。** 有统一回复消息类型声明，但问卷以外的允许/拒绝载荷、超时、重复回复与桌面任务关联仍需平台或实测补全。
5. **桌面原生公共客户端授权。** 本轮未找到该 Open API 的无密钥 PKCE 公共客户端流程。连接器文档的 PKCE 是 WorkBuddy 访问第三方 MCP 服务的另一个方向，不能借来替代开放 API 授权契约。

这些问题只阻塞相应新能力，不影响继续打磨已验证的本机联动。本文没有执行真实 API 或审批，以上未完成的运行验证均应在后续独立验证任务中处理。
