# WorkBuddy 联动体验优化清单

调研日期：2026-11-01。对照当前工作区源码与当日官方文档；本轮不修改产品代码、WorkBuddy 配置或插件，不触发真实任务与审批。官方能力详见《WorkBuddy官方开放能力调研-2026-11-01.md》。

后续实施更新：用户确认的普通客户端对话 P0 已实施并进入实机验收；接入新增 Notification，现为七项只读 Hook。本文保留实施前的机会清单与基线，最终行为、真实覆盖和限制以[普通对话 P0 验收](WorkBuddy普通对话P0验收-2026-11-01.md)为准。

## 判断

优先让现有联动更可信、更有信息量，再扩大双向操作能力。当前最直接的机会是：等待状态不因本地计时而消失、保留本轮回复摘要、把连接验真做得可操作、降低工具事件和提醒噪声。

必须区分三条通道：现有本机 Hook 观察；官方 OAuth 本地助理消息接口；官方云端任务与 ACP。后两者不能直接视为所有既有桌面任务的控制接口。

## 调研时的实际接入（实施前）

| 能力 | 当前状态与证据 |
|---|---|
| 安装 | 向 WorkBuddy 用户配置写六类 Hook：SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop、SessionEnd。保留其他配置、备份、固定 helper 路径；尚非原生插件。见 `Sources/LingChongDao/Connections/HookConfiguration.swift:78`、`ConnectionManager.swift:69`。 |
| 连接验真 | 已区分配置存在与收到真实活动；收到事件后显示“已收到活动”，保存内存中的 lastEventAt。不是实时在线检测。见 `ConnectionManager.swift:305`、`:370`。 |
| 会话展示 | 有标题、工作目录、工具活动、轮次结束、未读状态及来源身份隔离。提问仅识别特定工具名且须有稳定调用 ID。见 `Sources/IslandCore/HookNormalizer.swift:157`。 |
| 跳回任务 | 已对可信本机普通 WorkBuddy 来源、有效 UUID session_id 构建 `workbuddy://chat/<session_id>`，并指定准确 bundle；不满足条件时打开应用。见 `Sources/IslandCore/SessionNavigation.swift:36`、`Sources/LingChongDao/Models/AppModel.swift:293`。具体模板依据本机静态核验，不是已找到的公开 API 契约。 |
| 双向操作 | 无 WorkBuddy 岛内批准、拒绝或回答通道；问题回来源处理。见 `Sources/LingChongDao/Models/AppModel.swift:249` 与 `docs/Agent能力兼容性.md`。 |
| 版本边界 | WorkBuddy AI 可区分来源，但不自动安装到其独立 home，也不套普通版任务深链。当前 WorkBuddy 证据主要为静态/离线核验，尚无原生任务与审批全流程验收。 |

## 优化项与优先级

P0：下一轮优先；P1：随后迭代；P2：独立验证或新产品范围。成本为相对判断，不是排期承诺。

| 优先级 | 优化 | 用户得到什么 | 实施边界与验收 | 成本 |
|---|---|---|---|---|
| P0 | 等待超时改为“状态待核实”，保留回会话入口 | 走开两分钟后，仍知道 WorkBuddy 可能在等自己 | 目前提问固定最多 110 秒；到期变 idle、清未读，卡片从可见集合消失。不能无限认定仍待回答，也不能把本地过期当作来源已解决。等待观测与响应通道有效期分开；匹配结果、新轮次、明确结束才消除等待。验收：超过 110 秒、迟到结果、下一轮和同会话并发问题。 | 中 |
| P0 | 保留本轮回复摘要 | 不必每次打开 WorkBuddy 才知道刚才输出了什么 | normalizer 已读取 last_assistant_message，Stop 分支却无条件替换成固定文案。仅在实际收到可信摘要时显示截断文本，维持“本轮结束”，不宣称任务成功；不读取私人转录补齐。验收有/无摘要、长文本、多行、敏感文本和中断场景。 | 低至中 |
| P0 | 将连接检查升级为一次可完成的验证流程 | 安装后能明确知道同步是否生效、卡在哪一步 | 沿用已有 installed/connected，补“打开 WorkBuddy → 开新任务 → 收到开始/工具/结束”的验真进度与最近事件时间；详细诊断折叠。没有事件时显示“尚未验证”，不显示离线。升级后按版本重新验真。 | 中 |
| P0 | WorkBuddy 原生场景验收与兼容档案 | 避免看起来接好了，实际遇到提问或失败就失准 | 用用户明确发起的低风险任务验证：普通任务、AskQuestion、原生权限、失败、中断、重启、并发任务、冷启动跳转。先记录脱敏事件名/字段，再决定是否扩 Hook。支持矩阵按版本与事件标记，不拿 CodeBuddy CLI 或 IDE 测试代替 WorkBuddy。 | 中 |
| P1 | 工作进展用人能读懂的动作，并合并高频变化 | 从工具原名和刷屏变成“整理表格”“生成文档”等稳定进展 | 优先依据可靠工具名/描述映射；未知工具保留原名，不能凭模型猜任务进度。短间隔合并工具事件；错误与等待立即呈现，不被节流吞掉。 | 中 |
| P1 | 补充失败、等待、通知和子任务观察 | 异常及时出现，多 Agent 工作有可理解的进展 | 当前安装的六 Hook 不含 PermissionRequest、Notification、PostToolUseFailure、StopFailure、SubagentStart/Stop。官方 WorkBuddy 页未列完整事件协议，须逐项原生实测；已有 normalizer 能解析一些事件不代表来源会发。先只读提醒并跳回来源；工具失败不能一律判主任务失败。 | 中至高，依验证 |
| P1 | 完成、异常、待确认的提醒分级与免打扰 | 该打断时打断，普通活动安静展示 | WorkBuddy 官方设置已提供完成/确认/中断系统通知。灵宠岛以跨应用汇总和持续待办为价值：运行只更新，待处理优先；用户在来源前台时减少额外声音/震动。无法取得官方通知 ID 时，不能承诺跨应用精确去重；提供简洁策略开关即可。 | 中 |
| P1 | 原生插件作为可选分发方式 | 更容易在 WorkBuddy 内发现、管理、关闭灵宠岛接入 | 官方支持 Hook 插件和第三方市场 GUI 安装。先验证可发布市场与安装流程，再考虑迁移；迁移成功后精确移除旧自有 Hook，避免双重上报。未找到本地目录、一键安装链接或官方无人值守 CLI 契约，不直接写内部插件注册表。 | 中至高 |
| P1 | 任务切换与分组更适合办公场景 | 同时跑几个任务时，先看到需要自己处理的任务 | 保留现有精确回会话能力，强化任务名和紧急状态；缺少可靠工作区/任务分组 ID 时只按已知字段分组。官方任务管理有“待确认、完成未读、失败、进行中”语义，但只同步可靠观测到的状态，不照搬一个取不到的数据模型。 | 中 |
| P1 | 来源退出、岛重启后的恢复提示 | 不把已经失联的任务一直显示成运行中，也不让重启后的空列表令人误解 | 当前任务仅存内存，岛未运行时 helper 不缓冲事件，来源退出也未必有终态。可先显示“来源已退出/状态待确认”，提供打开与手动收起；如增加最小元数据恢复，需同步隐私说明和清理策略，不自动读取聊天数据库。无后续事件不能判成功或失败。验收时另观察 Stop 后紧跟 SessionEnd 是否过早清除结束未读。 | 中 |
| P2 | 本地 MCP 登记活动与产物 | 任务结束后，卡片能直接打开刚生成的文件 | 官方支持本地 stdio MCP，可提供小范围工具让 WorkBuddy 登记结果文件或活动说明；这补充当前 Hook 未结构化的语义信息。调用依赖 AI，不能作为必达的完成信号。先验证能否可靠关联当前 session；本地路径仅允许受约束的文件引用，不接受任意执行命令。 | 中至高 |
| P2 | 从灵宠岛把文本、文件交给 WorkBuddy | 拖文件或输入一句话即可进入 WorkBuddy 新任务 | 官方第三方分享支持预填与用户编辑发送。适合入口为“交给 WorkBuddy”，不是“继续当前任务”。PC 5.8.0+，需开发者应用、审核与服务端签名等条件；不要将私钥放桌面包。先确认开发者资格、服务成本与签名文档一致性。 | 高 |
| P2 | OAuth 本地助理：在岛上发起任务、看回复、回答问题 | 联动从被动状态展示扩展为受授权的任务入口 | 本地助理有在线查询、发消息、增量取消息及 permission_response；公开发送接口未给任意桌面 sessionId/taskId 定位参数。只能先验证该通道创建/关联的会话，不能承诺回答所有现有 Hook 任务的问题。在线表示本地助理连接状态，不等于每个任务仍在运行。 | 高 |
| P2 | 云端后台任务与产物收件箱 | 本机关闭后仍可关注云任务结果，回岛查看产物 | 官方云端任务 REST 与 ACP SSE/JSON-RPC 有任务状态和产物/权限协议。这是新的任务来源，独立标为云端，与本地 Hook 去重/关联需要可靠 ID；不拿云端审批回包套本机。仅在产品决定做云任务时投入。 | 高 |

## 建议第一批产品范围

1. 把已过本地时限的提问保留为“状态待核实”，提供打开会话和手动收起。
2. 本轮结束卡展示实际收到的简短回复，保留结束状态与结果成功的区别。
3. 连接页展示最近活动时间，并提供轻量验真步骤；技术详情保持折叠。
4. 做一轮 WorkBuddy 原生任务测试，按真实观察结果决定第二批事件支持。

这四项直接改善现有用户的可信度和信息量，且不需要先引入开发者账号、云服务或第二套任务系统。

## 暂不承诺

- 任意现有 WorkBuddy 会话的岛内批准、拒绝、回答、取消、重试或读未读双向同步：本轮未证实完整桌面公开契约。
- 精确完成百分比、所有产物自动读取、所有历史任务恢复：当前六 Hook 不足以提供依据。
- 官方宠物动画/当前选择同步：未找到公开读取协议。
- 一键原生插件安装与自动覆盖内部注册表：官方公开文档仅确认 GUI 市场安装流程。
